## Context

`ChatInterface.vue` 是 Vue 3 `<script setup lang="ts">` 单文件组件，已经定义 `messages`、头像、占位文案和禁用状态等 props，以及 `send`/`typing` 事件和 `ChatMessage` 类型。模板与脚本包含基础骨架及若干 TODO；项目使用 Vite、Vue、TypeScript 和 UnoCSS，测试页通过 `messages` prop 和 `send` 事件模拟助手回复。动机与范围见 `proposal.md`，行为契约见 `specs/chat-message-flow/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在单个组件边界内完成六项消息流行为，保持现有 props、事件和消息类型兼容。
- 让消息渲染、输入状态、表情选择、时间与头像元数据、滚动行为可通过自动化检查和测试页人工复核。
- 以小步提交方式实施，每项需求独立验证并在用户上传后再推进下一项。

**Non-Goals:**

- 不新增后端接口、消息持久化、真实网络发送或流式响应协议。
- 不重构 Pinia chat store、其他聊天布局或多模态输入组件。
- 不引入完整第三方表情库；使用组件现有的常用表情集合即可。

## Decisions

### 1. 保持组件本地消息状态与现有事件契约

继续以 `messageList` 作为渲染状态，发送时先追加本地用户消息，再通过现有 `send(content, images?)` 事件交给父组件。这样测试页无需改动，未来接入真实服务时仍可由父组件回写助手消息。相比直接修改 Pinia store，这种方案影响面小且符合当前组件的 props/emit 设计。

### 2. 用角色驱动的模板类和固定元数据布局

消息行根据 `user`/`assistant` 角色决定对齐、气泡颜色、头像位置和时间文字颜色；正文使用预格式化换行与最大宽度。头像优先级为“单条消息覆盖值 → 角色默认 prop”，并为图片设置固定尺寸和角色化替代文本。相比复制两套模板，统一循环可避免显示逻辑分叉。

### 3. 通过原生 textarea 光标选择实现表情插入

保留 textarea 作为唯一编辑器，在选择表情前记录 `selectionStart`/`selectionEnd`，将表情插入两者之间，再恢复光标到插入文本之后；没有有效选择范围时追加到末尾。相比 contenteditable 或第三方编辑器，原生控件依赖少、换行和键盘行为可预测。

### 4. 以 nextTick 后的容器 scrollTo 实现滚动

统一封装滚动到底部的动作，在挂载、外部消息替换/追加和本地消息追加后等待 DOM 更新，再调用容器 `scrollTo({ top: scrollHeight, behavior: 'smooth' })`。相比依赖消息元素选择器，容器高度方案能覆盖异步内容高度变化且不要求额外 DOM 标记。

### 5. 测试采用“单项验收 + 门禁”节奏

优先使用项目已有的 TypeScript/Vue 构建与测试页进行快速回归；若组件自动化环境可用，为每项能力补充最小组件测试，覆盖渲染、事件、光标插入和滚动调用。任务按六项需求严格串行，每项后记录测试命令/结果并暂停等待用户上传确认。这样既满足用户的协作流程，也避免多个未验证改动叠加。

## Risks / Trade-offs

- [异步助手回复可能让发送状态与父组件消息更新交错] → 本地消息使用稳定 ID，状态更新只定位对应消息；外部列表更新继续通过规范化函数处理。
- [平滑滚动在测试环境或不支持 scrollTo 的浏览器中不可用] → 将滚动动作集中封装，测试中使用 mock/能力检测；生产环境保留直接设置 scrollTop 的回退。
- [图片加载会改变消息高度] → 滚动在列表更新后执行，必要时在头像/图片加载后再次触发同一滚动入口；不引入复杂虚拟列表。
- [仅使用常用表情集合覆盖范围有限] → 本次只承诺集合内选择和插入，不把完整 Unicode 搜索纳入范围。

## Migration Plan

1. 在 `ChatInterface.vue` 内按任务顺序实现并为当前需求运行检查。
2. 每项检查通过后暂停，等待用户上传当前改动；继续时从下一项任务恢复。
3. 六项完成后运行 `vue-tsc`、ESLint、生产构建及完整测试页回归。
4. 若回归失败，回退到最近一个已通过门禁的提交；不需要数据迁移或后端回滚。
