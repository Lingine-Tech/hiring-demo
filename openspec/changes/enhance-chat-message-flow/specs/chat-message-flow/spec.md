## Purpose

为测试页面提供完整、可预测的聊天消息流体验，使用户能够清晰区分双方消息、发送文本和表情，并在浏览消息元数据时始终看到头像、时间和最新内容。

## ADDED Requirements

### Requirement: 消息气泡按角色区分

聊天界面 MUST 将用户消息与助手消息渲染为可辨识的不同气泡，并分别靠右和靠左排列；消息正文 MUST 保留换行并在长文本处换行，不能撑破消息区域。

#### Scenario: 用户和助手消息分别对齐

- **WHEN** 消息列表同时包含 `user` 和 `assistant` 角色的消息
- **THEN** 用户消息显示在右侧并使用发送方样式，助手消息显示在左侧并使用接收方样式

#### Scenario: 多行长文本可读

- **WHEN** 消息正文包含换行或超过气泡最大宽度
- **THEN** 界面保留换行并在气泡内部折行，消息列表不发生横向溢出

### Requirement: 文本消息可发送

聊天界面 MUST 支持通过发送按钮或不带 Shift 的 Enter 发送文本；发送内容 MUST 去除首尾空白，空内容、禁用状态或已有发送任务时 MUST 不发送。成功触发发送后，输入框 MUST 清空，消息 MUST 立即出现在列表中并显示发送中状态，同时向父组件发出包含清理后文本的 `send` 事件；发送状态结束后消息 MUST 显示已发送状态。

#### Scenario: 点击按钮发送有效文本

- **WHEN** 用户输入包含有效字符的文本并点击发送按钮
- **THEN** 清理后的文本以用户消息出现在列表中，输入框被清空，并触发一次 `send` 事件

#### Scenario: Enter 发送而 Shift+Enter 换行

- **WHEN** 输入框聚焦且用户按下 Enter
- **THEN** 文本被发送且浏览器默认换行行为被阻止
- **WHEN** 用户按下 Shift+Enter
- **THEN** 文本不发送，输入框新增换行

#### Scenario: 阻止无效或重复发送

- **WHEN** 输入仅包含空白、组件被禁用或消息仍处于发送中
- **THEN** 发送按钮不可用，且点击或键盘操作都不会新增消息或触发 `send` 事件

### Requirement: 表情选择器支持插入

聊天界面 MUST 提供可切换显示的常用表情选择器。选择表情后 MUST 将其插入输入框当前光标位置，保留光标前后已有文本，并关闭选择器；选择器按钮 MUST 可通过键盘访问并具有可理解的标签。

#### Scenario: 打开和关闭表情选择器

- **WHEN** 用户激活表情按钮
- **THEN** 常用表情面板显示；再次激活按钮时面板隐藏

#### Scenario: 在光标位置插入表情

- **WHEN** 输入框中存在文本且光标位于文本中间，用户选择一个表情
- **THEN** 表情插入光标处，原有文本顺序保持不变，面板关闭，输入框仍可继续编辑

### Requirement: 消息显示时间戳

每条消息 MUST 显示由其时间戳生成的小时和分钟，并使用当前界面的本地化时间格式；无效时间戳 MUST 回退为可渲染的当前时间或隐藏空值，不能导致组件渲染异常。

#### Scenario: 显示有效时间

- **WHEN** 消息带有有效的 Date、时间字符串或数字时间戳
- **THEN** 气泡元数据显示对应的本地化小时和分钟

#### Scenario: 处理无效时间

- **WHEN** 消息时间戳无法解析
- **THEN** 消息仍正常显示，时间字段采用安全回退，不抛出运行时错误

### Requirement: 消息显示对应头像

用户和助手消息 MUST 分别显示用户头像和助手头像；当单条消息提供头像时 MUST 优先使用该头像，否则使用组件传入的默认头像。头像 MUST 提供与消息角色相符的替代文本，并保持固定尺寸以避免列表布局跳动。

#### Scenario: 使用默认头像

- **WHEN** 消息没有单条头像覆盖值且组件提供用户或助手默认头像
- **THEN** 对应角色位置显示组件默认头像

#### Scenario: 使用单条消息头像覆盖

- **WHEN** 消息提供自定义头像地址
- **THEN** 该消息显示自定义头像，而不影响其他消息的头像

### Requirement: 自动滚动到最新消息

消息视口 MUST 在组件首次挂载、外部消息列表更新以及本组件发送新消息后滚动到列表底部，以便最新消息可见；滚动过程 SHOULD 使用平滑行为，且在消息内容更新后执行，避免滚动到过期高度。

#### Scenario: 初始消息加载到底部

- **WHEN** 组件挂载时已有多条消息且内容超出视口
- **THEN** 消息容器滚动位置位于底部，最新消息可见

#### Scenario: 外部追加消息

- **WHEN** 父组件向 `messages` 追加一条消息
- **THEN** 组件更新列表并在 DOM 更新后自动滚动到新消息

#### Scenario: 本地发送后滚动

- **WHEN** 用户发送消息导致列表新增用户气泡
- **THEN** 组件在新气泡渲染后滚动到底部

## 测试与协作门禁

每项需求完成后 MUST 先运行对应的组件或浏览器验收检查，并记录通过结果；未通过时不得进入下一项。每项检查通过后 MUST 暂停实现流程，等待用户将当前改动上传到指定 Git 仓库并明确允许继续，之后才开始下一项需求。
